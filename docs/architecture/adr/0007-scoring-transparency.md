# ADR-0007: Scoring transparency — deterministic scores, LLM only explains

- Status: accepted
- Date: 2026-07-18
- Deciders: Data & Applied-AI Engineer (virtual), Principal Solution Architect (virtual), repository owner

## Context

A core principle is "explainable rather than mysterious." We must not create a
black-box recovery score and then ask an LLM to justify it. Scores must be
deterministic, versioned, testable, and reproducible.

## Decision

All numerical scores (readiness, training-load, sleep quality, etc.) are
generated by **deterministic, versioned, tested analytics code**. The LLM may
explain computed results, identify patterns, summarize trends, and produce
coaching language — it never invents or overrides a score. Every score exposes
inputs, provenance, baseline, factor contributions, missing-data treatment,
confidence, algorithm version, plain-language explanation, and limitations.

## Consequences

- **Pros**: reproducibility; trust; auditability; golden tests pin outputs;
  LLM failures never corrupt scores.
- **Cons**: more upfront engineering than a black-box + LLM-justification
  approach; LLM explanations must be grounded in the computed factors.
- **Mitigations**: golden test cases per algorithm version; LLM output schema
  requires citing factor names and values; deterministic fallback when LLM is
  unavailable or output is malformed.
