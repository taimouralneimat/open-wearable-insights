# Rule: No Real Health Data

**Priority: CRITICAL — non-negotiable.**

## Statement

Real health data, credentials, tokens, exports, and identifiable information
must **never** be committed to this repository, placed in Cline context, included
in test fixtures, screenshots, logs, issues, pull requests, or AI prompts.

Development and automated testing use **synthetic or explicitly anonymized data
only**.

## What counts as real health data

- Any FIT, TCX, GPX, CSV, or JSON file exported from a real wearable device or
  health platform (Garmin Connect, Apple Health, Health Connect, WHOOP, etc.).
- Any screenshot, image, or log that contains real physiological measurements,
  activity records, sleep records, location traces, or identifiable metadata.
- Any database dump, Docker volume, or local app-data directory containing real
  records.
- Any pasted text containing real heart rate, HRV, sleep, steps, calories,
  stress, SpO2, respiration, training, or journal entries tied to a real person.

## What is allowed

- Synthetic data generated by `packages/test-data`.
- Synthetic FIT fixtures explicitly named `synthetic*.fit` under
  `packages/test-data/`.
- Fully anonymized data where all direct and indirect identifiers have been
  removed and re-identification is not reasonably possible.
- Publicly documented vendor capabilities described in
  `docs/product/parity-matrix.md` using only public information.

## Enforcement

- `.gitignore` excludes health exports, FIT files (except synthetic fixtures),
  database files, Docker volumes, tokens, local config, IDE secrets, Ollama
  models, real-data screenshots, signing files, and Garmin developer keys.
- CI runs `gitleaks` and a health-data guard that rejects any `*.fit` file
  outside `packages/test-data/**/synthetic*.fit` and `apps/garmin-connect-iq/**`.
- PRs must include a "No real health data" attestation checkbox.
- If real health data is accidentally staged, **stop**, do not push, and contact
  the maintainers privately so the history can be scrubbed.

## In Cline context

Never request, read, paste, or send real health data through Cline. If the user
provides a real export, refuse to ingest it into context and instead point them
to the local import folder outside the repository
(`docs/runbooks/importing-data.md`).
